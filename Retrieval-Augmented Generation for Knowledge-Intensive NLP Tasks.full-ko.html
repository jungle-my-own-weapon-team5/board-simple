지식 집약적 NLP 과제를 위한 검색 증강 생성

Patrick Lewis, Ethan Perez, Aleksandra Piktus, Fabio Petroni, Vladimir Karpukhin, Naman Goyal, Heinrich Kuttler, Mike Lewis, Wen-tau Yih, Tim Rocktaschel, Sebastian Riedel, Douwe Kiela

Conference paper 한국어 번역본

초록

대규모 사전학습 언어 모델은 사실 지식을 자신의 파라미터 안에 저장할 수 있으며, 하위 NLP 과제에 맞게 미세조정될 때 최신 수준의 결과를 달성하는 것으로 나타났다.

그러나 이러한 모델이 지식에 접근하고 지식을 정밀하게 조작하는 능력은 여전히 제한되어 있으며, 따라서 지식 집약적 과제에서는 과제별 구조를 갖춘 모델에 뒤처진다.

우리는 사전학습된 파라미터 기반 메모리 생성 모델을 비파라미터 기반 메모리와 결합하는 범용 미세조정 방법을 탐구한다.

여기서 비파라미터 기반 메모리는 Wikipedia의 조밀 벡터 인덱스이며, 사전학습된 신경 검색기를 통해 접근된다.

우리는 이 모델을 검색 증강 생성, 곧 RAG라고 부른다.

RAG 모델에서는 파라미터 기반 seq2seq 모델이 사전학습된 신경 검색기로부터 검색된 문서를 잠재 변수로 사용한다.

우리는 잠재 문서가 전체 생성 시퀀스에 대해 동일하다고 가정하는 모델과, 각 토큰마다 달라질 수 있다고 가정하는 모델을 비교한다.

우리는 다양한 지식 집약적 NLP 과제에서 RAG 모델을 미세조정하고 평가한다.

세 가지 오픈 도메인 QA 과제에서 RAG는 최신 성능을 달성하며, 파라미터 기반 seq2seq 모델과 과제 특화 검색-추출 아키텍처를 능가한다.

언어 생성 과제에서 RAG 모델은 강한 seq2seq 기준선보다 더 구체적이고 다양하며 사실적인 언어를 생성한다.

1. 서론

사전학습된 신경 언어 모델은 데이터로부터 상당한 양의 깊이 있는 지식을 학습하는 것으로 나타났다. [47]

이 모델들은 별도의 외부 메모리 없이도 하위 과제에 맞게 미세조정될 때 인상적인 결과를 보인다. [51, 52]

그러나 모델의 파라미터에만 의존하는 지식 접근 방식은 여러 약점을 갖는다.

파라미터 안에 저장된 지식은 어떤 근거에서 비롯되었는지 확인하기 어렵고, 업데이트하기 어려우며, hallucination을 일으킬 수 있다. [38]

또한 모델이 희귀하거나 구체적인 사실을 필요로 하는 입력을 처리할 때, 파라미터 기반 기억만으로는 충분하지 않을 수 있다.

반면 명시적 검색 시스템은 대규모 문서 모음에서 관련 문서를 찾아낼 수 있으며, 검색된 문서는 모델의 예측에 대한 근거로 제시될 수 있다.

하지만 검색만으로는 자연어 생성의 유창함과 일반화 능력을 충분히 제공하기 어렵다.

따라서 파라미터 기반 기억과 비파라미터 기반 기억을 결합하는 것은 지식 집약적 과제를 다루기 위한 자연스러운 방향이다. [20, 26, 48]

우리는 사전학습된 파라미터 기반 생성 모델에 비파라미터 기반 메모리를 부여하는 일반적인 미세조정 접근법을 제안하며, 이를 검색 증강 생성이라고 부른다.

우리가 구축한 RAG 모델에서 파라미터 기반 메모리는 사전학습된 seq2seq Transformer이고, 비파라미터 기반 메모리는 Wikipedia의 조밀 벡터 인덱스이며, 이는 사전학습된 신경 검색기로 접근된다.

우리는 이 구성요소들을 끝까지 함께 학습되는 확률 모델 안에서 결합한다.

검색기, 곧 Dense Passage Retriever(DPR)는 입력에 조건화된 잠재 문서를 제공하고, seq2seq 모델, 곧 BART는 입력과 잠재 문서에 함께 조건화되어 출력을 생성한다. [26, 32]

우리는 top-K 근사를 사용하여 잠재 문서를 주변화한다.

이 주변화는 모든 토큰에 대해 같은 문서가 책임을 진다고 보는 출력 단위 방식이거나, 서로 다른 토큰이 서로 다른 문서에 의해 책임질 수 있다고 보는 토큰 단위 방식일 수 있다.

T5나 BART와 마찬가지로 RAG는 어떤 seq2seq 과제에도 미세조정될 수 있으며, 이때 생성기와 검색기는 함께 학습된다. [51]

비파라미터 메모리를 사용해 시스템을 풍부하게 만들기 위한 아키텍처를 제안한 이전 연구는 많다.

예를 들어 메모리 네트워크, 스택 증강 네트워크, 메모리 계층은 특정 과제를 위해 처음부터 학습되는 비파라미터 메모리 구조를 제안했다. [64, 55, 25, 30]

이와 달리 우리는 파라미터 기반 메모리 구성요소와 비파라미터 기반 메모리 구성요소가 모두 사전학습되어 있으며 광범위한 지식을 미리 탑재한 설정을 탐구한다.

중요하게도 사전학습된 접근 메커니즘을 사용함으로써, 추가 학습 없이도 지식에 접근하는 능력이 존재한다.

우리의 결과는 생성과 함께 파라미터 기반 메모리와 비파라미터 기반 메모리를 결합하는 것이 지식 집약적 과제에 유익하다는 점을 강조한다.

여기서 지식 집약적 과제란 인간도 외부 지식원에 접근하지 않고는 합리적으로 수행하기 어렵다고 기대되는 과제를 뜻한다.

우리의 RAG 모델은 오픈 Natural Questions, WebQuestions, CuratedTrec에서 최신 수준의 결과를 달성하며, TriviaQA에서는 특수한 사전학습 목적을 사용하는 최근 접근법을 크게 능가한다. [29, 3, 2, 24]

이 과제들이 추출형 과제임에도 불구하고, 우리는 제약 없는 생성이 이전의 추출형 접근법보다 우수함을 발견했다.

지식 집약적 생성에서는 MS-MARCO와 Jeopardy 질문 생성을 실험하며, 우리의 모델이 BART 기준선보다 더 사실적이고 구체적이며 다양한 응답을 생성함을 발견했다. [1]

FEVER 사실 검증에서는 강한 검색 감독을 사용하는 최신 파이프라인 모델과 4.3% 이내의 결과를 달성한다. [56]

2. 방법

우리는 입력 시퀀스 x를 사용해 텍스트 문서 z를 검색하고, 목표 시퀀스 y를 생성할 때 이를 추가 문맥으로 사용하는 RAG 모델을 탐구한다.

그림 1에 보인 것처럼, 우리의 모델은 두 구성요소를 활용한다.

첫 번째 구성요소는 파라미터 η를 갖는 검색기 pη(z|x)이며, 질의 x가 주어졌을 때 텍스트 passage에 대한 top-K 절단 분포를 반환한다.

두 번째 구성요소는 파라미터 θ를 갖는 생성기 pθ(y_i|x,z,y_1:i-1)이며, 이전 i-1개 토큰 y_1:i-1, 원래 입력 x, 그리고 검색된 passage z의 문맥에 기반하여 현재 토큰을 생성한다.

검색기와 생성기를 끝까지 학습하기 위해 우리는 검색된 문서를 잠재 변수로 취급한다.

우리는 생성 텍스트에 대한 분포를 만들기 위해 잠재 문서를 서로 다른 방식으로 주변화하는 두 모델을 제안한다.

한 접근법인 RAG-Sequence에서는 모델이 각 목표 토큰을 예측하기 위해 같은 문서를 사용한다.

두 번째 접근법인 RAG-Token에서는 각 목표 토큰이 서로 다른 문서를 기반으로 예측될 수 있다.

아래에서는 두 모델을 형식적으로 소개한 뒤, pη와 pθ 구성요소, 그리고 학습 및 디코딩 절차를 설명한다.

2.1 모델

RAG-Sequence 모델은 하나의 동일한 검색 문서를 사용하여 완전한 시퀀스를 생성한다.

기술적으로 이 모델은 검색된 문서를 하나의 잠재 변수로 취급하고, top-K 근사를 통해 seq2seq 확률 p(y|x)를 얻기 위해 이를 주변화한다.

구체적으로 검색기를 사용해 상위 K개 문서를 검색하고, 생성기는 각 문서에 대해 출력 시퀀스 확률을 생성하며, 이후 이 확률들을 주변화한다.

pRAG-Sequence​(y|x)≈∑z∈top-k(p(⋅|x))pη​(z|x)​pθ​(y|x,z)=∑z∈top-k(p(⋅|x))pη​(z|x)​∏iNpθ​(yi|x,z,y1:i−1)p_{\text{\tiny{RAG-Sequence}}}(y|x)\;\approx\;\sum_{\mathclap{z\in\text{top-}k(p(\cdot|x))}}p_{\eta}(z|x)p_{\theta}(y|x,z)\;=\;\sum_{\mathclap{z\in\text{top-}k(p(\cdot|x))}}p_{\eta}(z|x)\prod_{i}^{N}p_{\theta}(y_{i}|x,z,y_{1:i-1})

RAG-Token 모델에서는 각 목표 토큰마다 서로 다른 잠재 문서를 뽑고 이에 따라 주변화할 수 있다.

이 방식은 답변을 생성할 때 생성기가 여러 문서의 내용을 선택할 수 있게 한다.

구체적으로 검색기를 사용해 상위 K개 문서를 검색한 뒤, 생성기는 각 문서에 대해 다음 출력 토큰의 분포를 생성하고, 이를 주변화한 다음 다음 출력 토큰에 대해 같은 과정을 반복한다.

pRAG-Token​(y|x)≈∏iN∑z∈top-k(p(⋅|x))pη​(z|x)​pθ​(yi|x,z,y1:i−1)p_{\text{\tiny{RAG-Token}}}(y|x)\;\approx\;\prod_{i}^{N}\;\sum_{z\in\text{top-}k(p(\cdot|x))}p_{\eta}(z|x)p_{\theta}(y_{i}|x,z,y_{1:i-1})

마지막으로 우리는 RAG가 목표 클래스를 길이 1의 목표 시퀀스로 간주함으로써 시퀀스 분류 과제에도 사용될 수 있음을 지적한다.

이 경우 RAG-Sequence와 RAG-Token은 동일하다.

2.2 검색기: DPR

검색 구성요소 pη(z|x)는 DPR에 기반한다. [26]

DPR은 이중 인코더 아키텍처를 따른다.

pη​(z|x)∝exp⁡(𝐝​(z)⊤​𝐪​(x))𝐝​(z)=BERTd​(z),𝐪​(x)=BERTq​(x)p_{\eta}(z|x)\propto\exp\left(\mathbf{d}(z)^{\top}\mathbf{q}(x)\right)\;\;\;\;\;\;\;\;\;\mathbf{d}(z)=\text{BERT}_{d}(z),\;\;\mathbf{q}(x)=\text{BERT}_{q}(x)

여기서 d(z)는 BERTBASE 문서 인코더가 생성한 문서의 조밀 표현이고, q(x)는 역시 BERTBASE에 기반한 질의 인코더가 생성한 질의 표현이다. [8]

문서에 대한 사전확률은 균등하다고 가정한다.

입력 x에 대해 관련 문서를 찾기 위해 최대 내적 검색을 수행한다. [23]

우리는 Wikipedia를 분할한 문서 인덱스를 사용하며, 각 문서는 약 100단어의 비중첩 텍스트 청크로 구성된다. [31, 26]

2.3 생성기: BART

생성 구성요소 pθ(y_i|x,z,y_1:i-1)는 어떤 인코더-디코더로도 모델링될 수 있다.

우리는 4억 개 파라미터를 가진 사전학습 seq2seq Transformer인 BART-large를 사용한다. [32, 58]

BART에서 생성할 때 입력 x와 검색된 내용 z를 결합하기 위해 우리는 단순히 둘을 이어 붙인다.

BART는 노이즈 제거 목적함수로 사전학습되어 있으며, 텍스트 생성, 번역, 이해 과제에서 강한 기준선이다. [32]

2.4 학습

우리는 어떤 문서가 검색되어야 하는지에 대한 직접 감독 없이 검색기와 생성기를 공동으로 학습한다.

입력-출력 쌍이 주어지면, 모델은 정답 출력의 음의 로그 가능도를 최소화하도록 학습된다. [28]

문서는 잠재 변수이므로, 학습 목표는 검색된 상위 K개 문서에 대한 주변화 가능도에 기반한다.

우리는 문서 인코더를 고정하고 문서 인덱스를 사전에 계산한다. [20]

학습 중에는 질의 인코더와 생성기 파라미터가 업데이트된다.

검색 인덱스 자체는 고정되어 있으므로 효율적인 최대 내적 검색을 사용할 수 있다.

2.5 디코딩

테스트 시점에서 RAG-Sequence와 RAG-Token은 arg max_y p(y|x)를 근사하기 위한 서로 다른 방법을 필요로 한다.

RAG-Token 모델은 표준적인 자기회귀 seq2seq 생성기로 볼 수 있으며, 각 단계의 전이 확률은 검색 문서에 대해 주변화된다.

따라서 표준 빔서치를 사용해 디코딩할 수 있다.

RAG-Sequence에서는 전체 시퀀스에 대해 하나의 잠재 문서가 사용되므로 디코딩이 더 어렵다.

우리는 각 문서별로 후보 시퀀스를 생성하고, 이 후보들을 전체 주변화 확률로 다시 점수화하는 접근을 사용한다.

짧은 답변 과제에서는 더 철저한 디코딩이 유리할 수 있고, 긴 생성 과제에서는 빠른 디코딩이 더 실용적이다.

3. 실험

우리는 RAG가 지식 집약적 NLP 과제에서 얼마나 효과적인지 평가하기 위해 네 종류의 과제를 고려한다.

이 과제들은 오픈 도메인 질의응답, 추상적 질의응답, 질문 생성, 사실 검증이다.

모든 과제에서 모델은 입력만 받고, 필요한 지식은 검색 인덱스에서 찾아야 한다. [31, 26, 23, 37]

3.1 오픈 도메인 질의응답

오픈 도메인 QA 과제에서는 모델이 질문을 입력으로 받고, 대규모 문서 집합에서 답을 찾은 뒤 짧은 답변을 생성해야 한다. [20]

우리는 Natural Questions, TriviaQA, WebQuestions, CuratedTrec를 사용한다. [29, 24, 3, 2]

이 과제들은 답변이 대체로 짧기 때문에 Exact Match가 주요 평가 지표로 사용된다.

우리는 추출형 모델과 달리 답변 문자열을 제약 없이 생성한다. [5, 7, 31, 26, 52]

3.2 추상적 질의응답

RAG의 자연어 생성 능력을 지식 집약적 환경에서 시험하기 위해 우리는 MS MARCO NLG 과제 v2.1을 사용한다. [43]

이 과제는 질문, 각 질문에 대해 검색 엔진이 검색한 열 개의 금 passage, 그리고 검색된 passage에서 주석된 완전한 문장 답변으로 구성된다.

우리는 MSMARCO를 오픈 도메인 추상적 QA 과제로 다루기 위해 제공된 passage를 사용하지 않고 질문과 답변만 사용한다.

MSMARCO에는 금 passage에 접근하지 않고는 참조 답변과 일치하는 방식으로 답할 수 없는 질문이 일부 포함되어 있다.

예를 들어 “Volcano, CA의 날씨는 어떤가?”와 같은 질문은 금 passage 없이는 참조 답변과 맞추기 어렵다.

따라서 금 passage를 사용하지 않을 경우 성능은 더 낮아질 것이다.

3.3 Jeopardy 질문 생성

우리는 검색 증강 생성이 더 풍부한 지식 기반 질문을 생성할 수 있는지 평가하기 위해 Jeopardy 질문 생성 과제를 사용한다. [10]

입력은 답변 엔티티이며, 목표는 해당 답변을 요구하는 Jeopardy 스타일 질문을 생성하는 것이다.

이 과제는 특정 인물, 작품, 장소, 사건에 대한 구체적 지식을 요구하므로 RAG의 외부 메모리 활용 능력을 평가하기에 적합하다.

3.4 사실 검증

우리는 FEVER 데이터셋을 사용해 사실 검증을 평가한다. [56]

입력은 자연어 주장이고, 모델은 그 주장이 지지됨, 반박됨, 또는 정보 부족 중 어느 범주에 속하는지 예측해야 한다.

FEVER는 외부 증거 문서를 필요로 하므로 검색 기반 접근이 특히 중요하다. [56]

3.5 구현 세부사항

우리는 모든 RAG 모델을 BART-large와 DPR 검색기를 기반으로 구현한다.

검색 인덱스는 Wikipedia dump를 passage 단위로 나누어 구성한다.

학습과 평가에서 RAG-Sequence와 RAG-Token을 모두 비교한다.

과제별로 적절한 검색 문서 수와 디코딩 방법을 사용한다.

4. 결과

우리는 결과를 과제별로 보고하고, 이후 생성 다양성, 사실성, 검색된 문서의 역할, 지식 갱신 가능성에 대한 추가 분석을 제공한다.

4.1 오픈 도메인 질의응답

RAG는 오픈 도메인 QA에서 강한 결과를 달성한다.

Natural Questions, WebQuestions, CuratedTrec에서는 최신 수준의 결과를 달성하고, TriviaQA에서는 특수 사전학습 목적을 사용하는 최근 접근법을 크게 능가한다. [29, 3, 2, 24]

흥미롭게도 이 과제들은 전통적으로 추출형 QA로 다루어졌지만, RAG의 제약 없는 생성 방식은 이전 추출형 접근법보다 좋은 성능을 보인다.

이는 생성 모델이 검색된 문서를 활용해 정답 문자열을 직접 생성할 수 있음을 보여준다.

4.2 추상적 질의응답

MS-MARCO NLG에서 RAG 모델은 강한 생성 기준선과 비교된다. [4]

검색된 문서에 조건화된 생성은 답변을 더 구체적으로 만들 수 있지만, 금 passage를 사용하지 않는 설정은 과제를 더 어렵게 만든다.

결과는 RAG가 외부 지식을 활용해 자연어 답변을 생성할 수 있음을 보여준다.

4.3 Jeopardy 질문 생성

Jeopardy 질문 생성에서 RAG 모델은 더 구체적이고 사실적으로 정확한 응답을 생성한다.

그림 2는 하나의 예시를 보여준다.

“Sun”을 생성할 때 posterior는 “The Sun Also Rises”를 언급하는 문서 2에서 높다.

마찬가지로 “A Farewell to Arms”가 생성될 때는 문서 1이 posterior를 지배한다.

흥미롭게도 각 책 제목의 첫 토큰이 생성된 뒤에는 문서 posterior가 평평해진다.

이 관찰은 생성기가 특정 문서에 의존하지 않고도 제목을 완성할 수 있음을 시사한다.

다시 말해 모델의 파라미터 기반 지식만으로도 제목을 완성하기에 충분하다.

우리는 BART 단독 기준선에 부분 디코딩을 입력함으로써 이 가설을 뒷받침하는 증거를 발견한다.

BART는 부분 생성 문자열을 완성하여 해당 제목이 BART의 파라미터 안에 저장되어 있음을 보여준다.

이 예시는 파라미터 기반 메모리와 비파라미터 기반 메모리가 함께 작동하는 방식을 보여준다.

비파라미터 구성요소는 생성 방향을 안내하고, 파라미터 기반 메모리에 저장된 특정 지식을 끌어낸다.

4.4 사실 검증

FEVER에서 RAG는 검색된 문서를 바탕으로 주장에 대한 분류를 수행한다. [57, 35]

강한 검색 감독을 사용하는 파이프라인 모델에는 약간 뒤처지지만, RAG는 직접적인 증거 감독 없이도 경쟁력 있는 결과를 낸다.

이는 잠재 검색과 생성 기반 분류가 사실 검증에도 적용될 수 있음을 보여준다.

개발 세트 ablation은 검색 구성요소와 생성 구성요소가 모두 중요한 역할을 한다는 점을 보여준다.

4.6 생성 다양성

RAG 모델은 BART 기준선보다 더 다양한 생성을 만들어낸다.

이는 검색된 문서가 생성 과정에 추가적인 정보원을 제공하기 때문이다.

고유 trigram 비율은 RAG의 출력이 더 반복적이지 않고 더 다양한 표현을 포함함을 보여준다. [33, 59, 39]

4.7 사실성 및 구체성

인간 평가는 RAG 생성물이 BART 생성물보다 더 사실적이고 구체적인 경우가 많음을 보여준다.

외부 지식에 근거하는 생성은 환각을 줄이는 데 도움이 된다.

그러나 검색된 문서가 부정확하거나 편향되어 있다면 생성 결과도 그 영향을 받을 수 있다.

4.8 지식 갱신

RAG와 같은 비파라미터 메모리 모델의 장점은 테스트 시점에 지식을 쉽게 업데이트할 수 있다는 것이다.

T5나 BART와 같은 파라미터 전용 모델은 세계가 변할 때 행동을 업데이트하기 위해 추가 학습이 필요하다.

이를 보이기 위해 저자들은 서로 다른 시점의 Wikipedia dump를 사용해 인덱스를 구축하고, 최신성이 필요한 질문에 대한 성능을 비교한다. [5]

문서 인덱스를 업데이트하는 것만으로 모델의 지식 접근이 바뀔 수 있다는 점은 RAG의 중요한 실용적 장점이다.

5. 관련 연구

이전 연구는 검색이 독립적으로 고려될 때 다양한 NLP 과제에서 성능을 향상시킨다는 점을 보여주었다.

이러한 과제에는 오픈 도메인 질의응답 [5, 29], 사실 확인 [56], 사실 완성 [48], 장문 질의응답 [12], Wikipedia article generation [36], 대화 [41, 65, 9, 13], 번역 [17], 그리고 언어 모델링 [19, 27] 이 포함된다.

오픈 도메인 질의응답 시스템은 일반적으로 검색기와 reader를 결합한다.

검색기는 관련 문서를 찾고, reader는 해당 문서에서 답을 추출한다.

우리의 접근은 reader가 추출에 제한되지 않고 답변을 생성한다는 점에서 다르다.

검색을 사용하지 않는 범용 NLP 아키텍처에 대한 연구도 큰 성공을 거두었다. [60, 61, 49, 8, 50, 32, 51, 52]

BERT, GPT, BART, T5 같은 모델은 대규모 사전학습과 미세조정을 통해 여러 과제에서 강한 결과를 낸다.

그러나 이러한 모델은 외부 문서를 명시적으로 검색하지 않으므로 지식 갱신과 근거 제시에 제한이 있다.

정보 검색 분야에서는 문서를 검색하는 방법에 대한 연구가 많으며, 최근에는 사전학습된 신경 언어 모델을 사용하는 조밀 검색이 발전했다. [44, 26]

DPR은 우리의 검색 구성요소와 밀접하게 관련된다. [26]

우리의 문서 인덱스는 신경망이 attend할 수 있는 대규모 외부 메모리로 볼 수 있으며, 이는 메모리 네트워크와 유사하다. [64, 55]

하지만 RAG는 사전학습된 검색기와 사전학습된 생성기를 결합하고, 대규모 Wikipedia 인덱스를 사용한다는 점에서 차별적이다.

우리의 방법은 검색 후 편집 방식과도 일부 유사하다. [18, 22, 21]

그 접근에서는 주어진 입력에 대해 유사한 학습 입력-출력 쌍을 검색한 뒤, 이를 편집하여 최종 출력을 만든다.

이러한 접근은 기계번역과 의미 파싱을 포함한 여러 영역에서 성공을 보였다. [18, 22, 21]

우리의 접근은 검색된 항목을 가볍게 편집하는 데 초점을 두기보다, 여러 검색 문서의 내용을 통합하고, 잠재 검색을 학습하며, 관련 학습 쌍이 아니라 증거 문서를 검색한다는 점에서 다르다.

그럼에도 RAG 기술은 이러한 설정에서도 잘 작동할 수 있으며, 유망한 향후 연구 방향이 될 수 있다.

6. 결론

이 연구에서 우리는 파라미터 기반 메모리와 비파라미터 기반 메모리에 접근할 수 있는 하이브리드 생성 모델을 제시했다.

우리는 이 모델을 검색 증강 생성이라고 부르며, 사전학습된 seq2seq 생성기와 사전학습된 신경 검색기를 결합한다.

RAG는 여러 지식 집약적 NLP 과제에서 강한 성능을 보였고, 특히 오픈 도메인 QA에서 최신 수준의 결과를 달성했다.

또한 RAG는 BART 기준선보다 더 구체적이고 사실적이며 다양한 생성을 만드는 경향을 보였다.

이 결과는 대규모 언어 모델의 파라미터 기반 지식과 외부 문서 기반 지식을 결합하는 것이 지식 집약적 자연어 처리에 효과적임을 보여준다.

더 넓은 영향

이 연구는 이전 연구에 비해 여러 긍정적인 사회적 이점을 제공한다.

실제 사실 지식, 이 경우 Wikipedia에 더 강하게 근거한다는 점은 생성 결과의 환각을 줄이고, 더 사실적인 생성을 가능하게 하며, 더 큰 통제 가능성과 해석 가능성을 제공한다.

RAG는 사회에 직접적인 이익을 줄 수 있는 다양한 시나리오에 사용될 수 있다.

예를 들어 의료 인덱스를 부여하고 해당 주제에 대한 오픈 도메인 질문을 하거나, 사람들이 자신의 업무를 더 효과적으로 수행하도록 돕는 방식으로 사용할 수 있다.

이러한 장점과 함께 잠재적 단점도 존재한다.

Wikipedia나 어떤 잠재적 외부 지식원도 완전히 사실적이고 편향이 전혀 없을 가능성은 낮다.

RAG는 언어 모델로 사용될 수 있으므로 GPT-2에 대해 제기된 것과 유사한 우려가 여기에도 적용된다. [50]

다만 그 정도는 다소 낮을 수 있다.

이러한 우려에는 악성 콘텐츠, 뉴스나 소셜 미디어에서의 허위 또는 오도성 콘텐츠 생성, 타인 사칭, 스팸 또는 피싱 콘텐츠 생성의 자동화가 포함된다. [54]

고도화된 언어 모델은 앞으로 수십 년 동안 다양한 직업의 자동화로 이어질 수도 있다. [16]

이러한 위험을 완화하기 위해 AI 시스템은 오도성 콘텐츠와 자동화된 스팸 또는 피싱에 대응하는 데 사용될 수 있다.

오픈 도메인 QA의 경우 우리는 RAG-Token 모델에 대해 15개 검색 문서를 사용한 테스트 수치를 보고한다.

RAG-Sequence 모델의 경우 우리는 50개 검색 문서를 사용한 테스트 결과를 보고하고, 답변이 일반적으로 짧기 때문에 Thorough Decoding 접근을 사용한다.

우리는 빔서치가 결과를 개선하지 않는다는 점을 발견했기 때문에 QA에서는 탐욕적 디코딩을 사용한다.

Open-MSMarco와 Jeopardy 질문 생성의 경우, RAG-Token과 RAG-Sequence 모두에 대해 10개 검색 문서를 사용한 테스트 수치를 보고하고, 기준선으로 BART-large 모델도 학습한다.

우리는 빔 크기 4를 사용하며, Thorough Decoding이 성능을 개선하지 않았기 때문에 RAG-Sequence 모델에는 Fast Decoding 접근을 사용한다.

부록 B. 인간 평가

그림 4는 인간 평가를 위한 사용자 인터페이스를 보여준다.

화면 위치에 따른 편향을 피하기 위해, 어떤 모델이 문장 A와 문장 B에 대응되는지는 각 예시마다 무작위로 선택되었다.

주석자는 인터넷을 사용해 주제를 조사하도록 권장되었으며, 전체 지침 탭에서 자세한 지침과 작업 예시를 제공받았다.

우리는 주석자의 정확도를 평가하기 위해 일부 금 문장을 포함했다.

두 명의 주석자는 이러한 예시에서 좋은 성과를 내지 못했으며, 그들의 주석은 결과에서 제거되었다.

부록 C. 학습 설정 세부사항

우리는 모든 RAG 모델과 BART 기준선을 Fairseq를 사용해 학습한다. [45]

최적화에는 Adam을 사용한다.

과제별로 학습률, 배치 크기, 총 학습 단계 수를 조정한다.

검색은 FAISS 기반 최대 내적 검색으로 수행된다.

문서 인코더는 고정되어 있으며, 질의 인코더와 생성기는 미세조정된다.

부록 D. 오픈 도메인 QA에 대한 추가 세부사항

오픈 도메인 QA에서는 하나의 질문에 대해 여러 답변 주석이 제공되는 경우가 많다.

추출형 모델은 일반적으로 학습 데이터를 준비할 때 문서 안에서 매칭을 찾기 위해 모든 답변 주석을 사용하므로 이러한 답변 주석을 활용한다.

RAG의 경우에도 Natural Questions와 WebQuestions에 대해 각 질문-답변 쌍을 별도로 사용하여 모델을 학습함으로써 여러 주석 예시를 활용하며, 이는 정확도를 약간 높인다.

TriviaQA의 경우 하나의 질문에 대해 유효한 답변이 많이 존재하는 경우가 많으며, 그중 일부는 이모지나 철자 변형처럼 적절한 학습 목표가 아닐 수 있다.

TriviaQA에서는 답변 후보가 해당 질의의 상위 1000개 문서에 나타나지 않으면 이를 필터링한다.

CuratedTrec의 답변은 정규표현식 형태로 주어진다. [20]

이는 답변 생성 모델에 적합하지 않은 이유로 제기되어 왔다.

이를 극복하기 위해 우리는 전처리 단계를 사용한다.

먼저 각 질의에 대해 상위 1000개 문서를 검색하고, 정규표현식 패턴과 가장 자주 매칭되는 답변을 지도 목표로 사용한다.

매칭이 발견되지 않으면 단순한 휴리스틱을 사용한다.

이 휴리스틱은 각 정규표현식에 대해 가능한 모든 순열을 생성하고, 정규표현식의 중첩 트리 구조 안에 있는 비결정적 기호를 공백으로 대체한다.

오픈 도메인 QA 커뮤니티에서는 QA 데이터셋의 테스트 데이터가 종종 제한되어 있고 독해 목적에 전용되어 있기 때문에 공개 개발 데이터셋을 테스트 데이터셋으로 사용하는 관행이 있다.

우리는 DPR에서 사용한 데이터셋 분할을 사용해 결과를 보고하며, 이는 오픈 도메인 QA의 일반적 관행과 일치한다.

TriviaQA의 경우 이 테스트 데이터셋은 공개 TriviaQA Web Development 분할이다.

부록 E. FEVER 세부사항

FEVER 분류의 경우 우리는 이전 연구의 관행을 따르며, 먼저 주장을 다시 생성한 뒤 최종 은닉 상태의 표현을 사용해 분류하고, 마지막으로 문서들에 걸쳐 주변화하여 클래스 확률을 얻는다. [32]

부록 F. Null 문서

우리는 주어진 입력에 대해 유용한 정보를 검색할 수 없는 경우를 모델링하기 위해 REALM과 유사한 “Null document” 메커니즘을 RAG에 추가하는 실험을 수행했다. [20]

여기서 k개의 문서가 검색되었다면, 우리는 추가로 빈 문서를 “검색”하고 null 문서에 대한 로짓을 예측한 뒤, k+1개의 예측에 대해 주변화한다.

우리는 null 문서에 대한 로짓을 모델링하기 위해 세 가지 방법을 탐구했다.

첫째, null 문서에 대한 문서 임베딩을 학습했다.

둘째, 정적인 학습 편향 항을 사용했다.

셋째, 로짓을 예측하는 신경망을 사용했다.

우리는 이 방법들이 성능을 개선하지 않는다는 점을 발견했으므로, 단순성을 위해 이를 생략한다.

유용한 검색 문서를 항상 검색할 수 없는 Open MS-MARCO의 경우, 모델은 검색으로부터 이익을 얻을 가능성이 낮은 질문에 대해 특정 문서 집합을 항상 검색하도록 학습하는 것을 관찰했다.

이는 null 문서 메커니즘이 RAG에 필요하지 않을 수 있음을 시사한다.

부록 G. 파라미터 수

우리의 RAG 모델은 DPR의 BERT-base 질의 인코더와 문서 인코더에 대한 학습 가능한 파라미터를 포함하며, 각각은 1억 1천만 개의 파라미터를 갖는다.

다만 우리는 문서 인코더 자체를 학습하지 않는다.

또한 BART-large로부터 4억 6백만 개의 학습 가능한 파라미터를 포함하며, 총 학습 가능한 파라미터 수는 6억 2천 6백만 개가 된다.

가장 좋은 성능을 보이는 폐쇄형 책, 곧 파라미터 전용 오픈 도메인 QA 모델은 110억 개의 학습 가능한 파라미터를 가진 T5-11B이다.

우리 모델과 가장 가까운 파라미터 수를 가진 T5 모델은 7억 7천만 개 파라미터를 가진 T5-large이며, 이는 Natural Questions에서 28.9 EM을 달성한다. [52]

이는 RAG-Sequence가 달성한 44.5보다 상당히 낮다.

따라서 하이브리드 파라미터/비파라미터 모델은 강한 오픈 도메인 QA 성능을 위해 훨씬 적은 학습 가능 파라미터를 필요로 함을 나타낸다.

비파라미터 메모리 인덱스는 학습 가능한 파라미터로 구성되지 않는다.

하지만 이 인덱스는 2,100만 개의 728차원 벡터, 곧 153억 개 값으로 구성된다.

이 값들은 메모리와 디스크 사용량을 관리하기 위해 8비트 부동소수점 정밀도로 쉽게 저장될 수 있다.

부록 H. 검색 붕괴

예비 실험에서 우리는 스토리 생성과 같은 일부 과제에서 검색 구성요소가 “붕괴”하여 입력과 관계없이 같은 문서를 검색하도록 학습하는 현상을 관찰했다. [11]

이러한 경우 검색이 붕괴된 뒤 생성기는 문서를 무시하도록 학습하고, RAG 모델은 BART와 동등하게 수행된다.

이는 RAG가 특히 외부 지식이 실제로 도움이 되는 지식 집약적 과제에 적합하다는 점을 시사한다.
