지식 집약적 NLP 과제를 위한 검색 증강 생성

초록

대규모 사전학습 언어 모델은 모델 파라미터 안에 사실 지식을 저장할 수 있으며, 하위 NLP 과제에 맞게 미세조정했을 때 뛰어난 성능을 보이는 것으로 알려져 있다. 하지만 이런 모델은 지식에 접근하고 조작하는 방식이 여전히 제한적이다. 따라서 지식 집약적 과제에서는 모델의 성능이 과제별 구조를 갖춘 별도 아키텍처에 뒤처지는 경우가 있다.

이 논문은 사전학습된 파라미터 기반 생성 모델과 비파라미터 기반 메모리를 결합하는 범용 미세조정 방법을 제안한다. 비파라미터 메모리는 Wikipedia의 조밀 벡터 인덱스이며, 사전학습된 신경 검색기를 통해 접근한다. 이 방식을 검색 증강 생성, 즉 RAG라고 부른다.

RAG 모델은 입력을 받아 관련 문서를 검색하고, 검색된 문서를 조건으로 삼아 답변이나 문장을 생성한다. 실험에서는 오픈 도메인 질의응답, 추상적 질의응답, 질문 생성, 사실 검증 등 여러 지식 집약적 NLP 과제에서 RAG가 강한 성능을 보이며, 파라미터만 사용하는 생성 모델보다 더 사실적이고 구체적인 출력을 만든다는 점을 보인다.

1. 서론

사전학습된 신경 언어 모델은 대량의 데이터에서 상당한 지식을 학습한다. 이런 지식은 모델의 파라미터 안에 압축되어 저장되며, BERT, GPT, BART, T5 같은 모델은 다양한 NLP 과제에서 높은 성능을 낸다. 그러나 파라미터 내부에만 지식을 저장하는 방식은 몇 가지 약점을 가진다. 지식을 갱신하기 어렵고, 모델이 어떤 근거를 사용했는지 해석하기 어려우며, 드문 사실이나 최신 사실을 정확히 다루기 어렵다.

반대로 검색 기반 시스템은 외부 문서 저장소를 사용한다. 문서를 명시적으로 검색하므로 지식을 갱신하기 쉽고, 답변의 근거를 확인할 수 있다. 하지만 검색 시스템만으로는 자연스러운 문장 생성이나 여러 문서의 정보를 조합하는 데 한계가 있다.

이 논문은 두 접근을 결합한다. 생성 모델은 언어를 유창하게 만들고, 검색기는 외부 지식에 접근한다. RAG는 입력 질문 또는 입력 문장에 대해 관련 문서를 검색한 뒤, 그 문서를 생성 모델의 추가 문맥으로 사용한다. 이때 검색된 문서는 잠재 변수처럼 취급되며, 검색기와 생성기를 함께 미세조정한다.

저자들은 인간도 외부 지식 없이 수행하기 어려운 과제를 지식 집약적 과제로 본다. 예를 들어 오픈 도메인 질의응답, 사실 검증, 특정 주제에 대한 질문 생성 등이 여기에 속한다. RAG는 이런 과제에서 파라미터 기반 기억과 외부 문서 기반 기억을 함께 사용한다는 점에서 장점이 있다.

2. 방법

RAG 모델은 입력 시퀀스 x를 사용해 텍스트 문서 z를 검색하고, 그 문서를 추가 문맥으로 사용해 목표 시퀀스 y를 생성한다. 모델은 두 구성요소로 이루어진다. 첫째는 검색기이며, 입력 x가 주어졌을 때 문서 z에 대한 확률분포를 반환한다. 둘째는 생성기이며, 입력 x, 검색 문서 z, 이전에 생성된 토큰들을 바탕으로 다음 토큰을 생성한다.

학습 과정에서는 검색된 문서를 직접 정답으로 주지 않는다. 대신 문서를 잠재 변수로 보고, 여러 후보 문서에 대한 생성 확률을 합산하거나 주변화하여 최종 확률을 계산한다. 이렇게 하면 어떤 문서를 검색해야 하는지에 대한 직접 라벨 없이도 검색기와 생성기를 함께 학습할 수 있다.

2.1 모델

논문은 두 가지 RAG 변형을 제안한다. 첫 번째는 RAG-Sequence이고, 두 번째는 RAG-Token이다. 두 모델 모두 상위 K개의 문서를 검색하지만, 검색 문서를 생성 과정에 사용하는 방식이 다르다.

RAG-Sequence는 하나의 검색 문서를 전체 출력 시퀀스를 생성하는 데 사용한다. 즉, 답변 전체가 같은 문서에 조건화된다. 검색기는 상위 K개 문서를 찾고, 생성기는 각 문서에 대해 전체 출력 시퀀스의 확률을 계산한다. 이후 문서별 확률을 주변화하여 최종 시퀀스 확률을 얻는다.

RAG-Token은 출력 토큰마다 서로 다른 검색 문서를 사용할 수 있다. 각 토큰을 생성할 때 상위 K개 문서에 대한 다음 토큰 확률을 계산하고 이를 주변화한다. 이 방식은 답변을 만들 때 여러 문서의 내용을 더 유연하게 조합할 수 있다.

시퀀스 분류 과제에서는 목표 클래스가 길이 1의 출력 시퀀스로 볼 수 있으므로, RAG-Sequence와 RAG-Token은 사실상 같은 형태가 된다.

2.2 검색기: DPR

검색 구성요소는 DPR(Dense Passage Retrieval)을 기반으로 한다. DPR은 질문 인코더와 문서 인코더를 따로 사용하는 이중 인코더 구조다. 질문과 문서를 각각 조밀 벡터로 변환하고, 두 벡터의 내적을 사용해 관련도를 계산한다.

문서 인코더는 Wikipedia 문서 조각을 벡터로 변환하고, 질문 인코더는 입력 질문을 벡터로 변환한다. 검색 시에는 질문 벡터와 가장 가까운 문서 벡터들을 찾는다. 논문에서는 Wikipedia를 100단어 단위의 분할 문서로 구성하고, 약 2,100만 개 문서 조각의 인덱스를 사용한다.

2.3 생성기: BART

생성 구성요소는 어떤 인코더-디코더 모델로도 구현할 수 있다. 논문에서는 4억 개 파라미터를 가진 BART-large를 사용한다. BART가 생성할 때 원래 입력 x와 검색된 문서 z를 함께 보도록, 두 텍스트를 단순히 이어 붙여 인코더 입력으로 사용한다.

2.4 학습

검색기와 생성기는 함께 학습된다. 어떤 문서가 검색되어야 하는지에 대한 직접 감독은 사용하지 않는다. 대신 정답 출력의 가능도를 최대화하도록 학습하면, 모델은 답을 잘 생성하는 데 도움이 되는 문서를 더 높은 확률로 검색하도록 조정된다. 문서 인덱스 자체는 학습 중 고정되며, 질문 인코더와 생성기 파라미터가 업데이트된다.

2.5 디코딩

테스트 시에는 RAG-Sequence와 RAG-Token의 디코딩 방식이 다르다. RAG-Token은 각 토큰 단계에서 문서별 확률을 합산해 일반적인 자기회귀 생성기처럼 빔서치로 디코딩할 수 있다.

RAG-Sequence는 전체 시퀀스가 하나의 문서에 조건화되므로 더 복잡하다. 논문은 각 문서별로 후보 시퀀스를 만든 뒤 재평가하는 방식과, 더 철저하게 후보를 수집해 주변화 확률을 계산하는 방식을 사용한다. 짧은 답변 과제에서는 철저한 디코딩이 유리하고, 긴 생성 과제에서는 빠른 디코딩이 실용적이다.

3. 실험

실험은 RAG가 지식 집약적 NLP 과제에서 얼마나 효과적인지 평가한다. 비교 대상에는 파라미터만 사용하는 생성 모델, 검색 기반 모델, 추출형 질의응답 모델, 기존의 강한 오픈 도메인 QA 시스템 등이 포함된다.

3.1 오픈 도메인 질의응답

오픈 도메인 QA에서는 질문만 주어지고, 모델은 대규모 문서 집합에서 필요한 정보를 찾아 짧은 답을 생성해야 한다. Natural Questions, TriviaQA, WebQuestions, CuratedTrec 등의 데이터셋을 사용한다. 평가는 Exact Match를 중심으로 진행된다.

3.2 추상적 질의응답

추상적 QA에서는 답이 단순한 짧은 문자열이 아니라 자연어 문장 형태로 생성된다. 논문은 MS MARCO NLG 과제를 사용한다. 원래 데이터에는 검색 엔진이 찾은 문서들이 포함되지만, RAG 실험에서는 질문과 답만 사용하여 오픈 도메인 생성형 QA로 다룬다. 따라서 금 문서가 있어야만 답할 수 있는 일부 질문에서는 성능이 낮아질 수 있다.

3.3 질문 생성

질문 생성 과제에서는 주어진 입력에 대해 적절한 질문을 생성한다. Jeopardy 스타일 질문 생성처럼 특정 답이나 주제에 맞는 질문을 만드는 과제를 포함한다. 검색된 문서는 생성 모델이 더 구체적이고 사실적인 질문을 만들도록 돕는다.

3.4 사실 검증

FEVER 데이터셋을 사용해 주어진 주장에 대해 참, 거짓, 정보 부족을 분류한다. RAG는 검색한 증거 문서를 바탕으로 주장을 재구성하고 분류 확률을 계산한다.

3.5 추가 분석

논문은 검색된 문서의 품질, 생성 결과의 다양성, 사실성, 지식 갱신 가능성도 분석한다. RAG가 실제로 외부 문서의 정보를 활용하는지, 그리고 파라미터만 사용하는 모델보다 더 구체적인 지식을 출력하는지를 확인한다.

4. 결과

RAG는 여러 지식 집약적 과제에서 강한 성능을 보였다. 특히 오픈 도메인 QA에서는 기존의 파라미터 기반 생성 모델보다 훨씬 높은 정확도를 보였고, 일부 데이터셋에서는 기존 최고 수준의 결과와 경쟁하거나 이를 넘어섰다.

4.1 오픈 도메인 질의응답 결과

Natural Questions, TriviaQA, WebQuestions, CuratedTrec에서 RAG는 BART나 T5 같은 폐쇄형 책 모델보다 좋은 성능을 보인다. 폐쇄형 책 모델은 모델 파라미터 안의 지식만 사용하지만, RAG는 Wikipedia 인덱스를 검색해 추가 근거를 사용한다. 이 차이가 지식 집약적 QA에서 큰 성능 차이로 이어진다.

RAG-Sequence와 RAG-Token 중 어느 모델이 항상 우월한 것은 아니지만, 짧은 답변을 요구하는 QA에서는 RAG-Sequence가 강한 결과를 보이는 경우가 많다. 이는 답변 전체가 하나의 일관된 증거 문서에 조건화되는 구조가 짧은 사실 답변에 잘 맞기 때문이다.

4.2 추상적 질의응답 결과

MS MARCO NLG에서 RAG는 검색된 문서를 활용해 더 구체적인 답변을 생성한다. 답변 품질은 Rouge-L, BLEU 등 생성 평가 지표로 측정된다. 금 문서를 사용하지 않기 때문에 일부 질문에서는 어려움이 있지만, RAG는 단순 생성 모델보다 외부 지식을 더 잘 활용한다.

4.3 질문 생성 결과

질문 생성에서는 RAG가 BART보다 더 다양하고 구체적인 질문을 생성한다. 검색된 문서가 배경 지식을 제공하기 때문에 생성 결과가 일반적 표현에 머무르지 않고 특정 사실을 포함할 가능성이 높아진다.

4.4 사실 검증 결과

FEVER 사실 검증에서도 RAG는 검색된 증거 문서를 활용해 좋은 성능을 보인다. 단순히 주장 문장만 보고 분류하는 것보다, 관련 문서를 함께 보는 방식이 사실 판단에 유리하다.

4.5 생성 다양성과 사실성

RAG는 파라미터만 사용하는 BART보다 더 다양한 출력을 생성하는 경향을 보인다. 서로 다른 문서가 생성 과정에 관여할 수 있으므로, 같은 입력에 대해서도 더 폭넓은 표현과 내용을 만들 수 있다. 또한 인간 평가에서는 RAG의 출력이 더 사실적이고 구체적이라는 평가를 받는다.

4.6 검색된 문서의 역할

분석 결과, RAG는 단순히 문서를 장식적으로 붙이는 것이 아니라 실제로 검색 문서를 활용한다. 검색된 문서가 정답과 관련 있을수록 답변 성능이 좋아지며, 검색 품질은 전체 RAG 성능의 중요한 요소다.

4.7 지식 갱신

RAG 같은 비파라미터 메모리 모델의 장점은 테스트 시점에 지식을 쉽게 갱신할 수 있다는 것이다. T5나 BART 같은 파라미터 전용 모델은 세상이 바뀌면 추가 학습이 필요하다. 반면 RAG는 문서 인덱스를 교체하거나 갱신함으로써 새로운 지식을 반영할 수 있다.

4.8 검색 문서 수

모델은 보통 5개 또는 10개의 잠재 문서를 사용해 학습된다. 실험에서는 이 둘 사이에 큰 성능 차이가 관찰되지 않았다. 다만 테스트 디코딩에서는 과제 특성에 따라 더 많은 문서를 고려할 수 있다.

5. 관련 연구

검색은 오래전부터 NLP 과제의 성능을 높이는 데 사용되어 왔다. 질의응답, 번역, 대화, 사실 검증 등 다양한 과제에서 검색된 문서를 별도의 입력으로 활용하는 방식이 연구되었다.

또 다른 흐름은 검색 없이 범용 사전학습 모델만으로 과제를 해결하는 접근이다. BERT, GPT, BART, T5 같은 모델은 사전학습과 미세조정을 통해 많은 과제에서 좋은 성능을 보였다. 하지만 이들은 외부 지식을 명시적으로 검색하지 않기 때문에 지식 갱신과 근거 제시에 한계가 있다.

정보 검색 분야에서는 문서를 더 잘 찾기 위한 신경 검색 모델이 발전해 왔다. DPR처럼 질문과 문서를 조밀 벡터로 표현하는 방식은 RAG의 검색 구성요소와 밀접하게 관련된다.

메모리 네트워크와 같은 모델은 외부 메모리를 신경망이 참조하도록 하는 접근을 제안했다. RAG의 문서 인덱스도 큰 외부 메모리로 볼 수 있다. 다만 RAG는 사전학습된 검색기와 생성기를 결합하고, Wikipedia 같은 대규모 지식 저장소를 사용한다.

검색 후 편집 방식도 관련이 있다. 이 방식은 비슷한 입력-출력 예시를 검색한 뒤 수정하여 최종 출력을 만든다. RAG는 검색된 예시를 가볍게 편집하는 것보다, 여러 증거 문서의 내용을 생성 과정에서 통합한다는 점이 다르다.

6. 결론

이 논문은 파라미터 기반 메모리와 비파라미터 기반 메모리에 함께 접근하는 하이브리드 생성 모델을 제시했다. RAG는 사전학습된 생성 모델과 검색 기반 문서 인덱스를 결합하여, 지식 집약적 NLP 과제에서 강한 성능을 보인다.

RAG는 오픈 도메인 QA, 추상적 QA, 질문 생성, 사실 검증에서 효과적이며, 파라미터만 사용하는 모델보다 더 구체적이고 사실적인 출력을 생성한다. 또한 문서 인덱스를 갱신함으로써 모델 전체를 다시 학습하지 않고도 지식을 업데이트할 수 있다는 실용적 장점이 있다.

더 넓은 영향

이 연구는 이전 작업보다 실제 사실 지식에 더 강하게 기반을 둔 모델을 제공한다는 점에서 긍정적인 사회적 이점을 가진다. Wikipedia 같은 외부 지식에 근거하므로 환각을 줄이고, 생성 결과의 사실성과 해석 가능성을 높일 수 있다. 의료 색인과 결합해 전문 질의응답에 쓰거나, 사람들이 업무를 더 효과적으로 수행하도록 돕는 등 다양한 활용 가능성이 있다.

동시에 잠재적 단점도 있다. Wikipedia나 어떤 외부 지식원도 완전히 사실적이고 편향이 없다고 보장할 수 없다. RAG도 언어 모델로 사용될 수 있으므로, 악용, 허위 또는 오해를 유발하는 콘텐츠 생성, 타인 사칭, 스팸이나 피싱 자동화 같은 우려가 존재한다. 고도화된 언어 모델은 장기적으로 일부 직업의 자동화에도 영향을 줄 수 있다.

감사의 글

저자들은 논문에 대해 사려 깊고 건설적인 피드백을 준 리뷰어들에게 감사한다. 또한 RAG 모델을 실행할 수 있는 코드를 오픈소스로 공개하는 데 도움을 준 HuggingFace에도 감사한다.

부록

부록 A. 디코딩 세부사항

오픈 도메인 QA에서는 RAG-Token 모델의 테스트 결과를 15개 검색 문서로 보고한다. RAG-Sequence 모델은 50개 검색 문서를 사용하며, 답변이 일반적으로 짧기 때문에 철저한 디코딩 방식을 사용한다. QA에서는 빔서치가 성능을 높이지 않아 탐욕적 디코딩을 사용한다.

Open-MS MARCO와 Jeopardy 질문 생성에서는 RAG-Token과 RAG-Sequence 모두 10개 검색 문서를 사용한다. 비교 기준으로 BART-large도 학습한다. 이 과제에서는 빔 크기 4를 사용하고, RAG-Sequence에는 빠른 디코딩을 사용한다.

부록 B. 인간 평가

인간 평가는 두 모델이 생성한 문장을 비교하는 사용자 인터페이스로 진행된다. 화면 위치 편향을 피하기 위해 어떤 모델의 출력이 문장 A 또는 문장 B가 되는지는 각 예시마다 무작위로 정한다. 평가자들은 인터넷을 사용해 주제를 조사하도록 권장되며, 자세한 지침과 예시를 제공받는다. 평가자 품질을 확인하기 위해 일부 정답 문장을 포함했고, 품질이 낮은 평가자의 주석은 결과에서 제외했다.

부록 C. 학습 설정

모든 RAG 모델과 BART 기준 모델은 Fairseq를 사용해 학습한다. 실험은 과제별로 학습률, 배치 크기, 디코딩 설정 등을 조정하여 수행된다. 검색 인덱스는 FAISS 기반의 최대 내적 검색을 사용한다.

부록 D. 오픈 도메인 QA 세부사항

오픈 도메인 QA에서는 하나의 질문에 여러 정답 주석이 있는 경우가 많다. 추출형 모델은 이런 여러 정답을 문서 안에서 매칭하는 데 사용한다. RAG도 Natural Questions와 WebQuestions에서 여러 정답 예시를 각각 학습 예시로 사용해 정확도를 소폭 높인다.

TriviaQA에서는 하나의 질문에 여러 유효 답이 존재하며, 이 중 일부는 학습 목표로 적절하지 않을 수 있다. 따라서 상위 1000개 문서 안에 나타나지 않는 답 후보는 필터링한다.

CuratedTrec의 정답은 정규표현식 형태로 주어진다. 생성 모델 학습에 맞추기 위해 먼저 각 질문에 대해 상위 1000개 문서를 검색하고, 정규표현식과 가장 자주 매칭되는 답을 지도 목표로 사용한다. 매칭이 없으면 정규표현식에서 가능한 후보를 생성하는 휴리스틱을 사용한다.

오픈 도메인 QA 분야에서는 테스트 데이터가 제한된 경우가 많아 공개 개발 세트를 테스트 세트처럼 사용하는 관행이 있다. 논문도 DPR에서 사용한 데이터 분할을 따라 결과를 보고한다.

부록 E. FEVER 세부사항

FEVER 분류에서는 먼저 주장을 다시 생성한 뒤, 최종 은닉 상태 표현을 사용해 분류한다. 이후 문서별 예측을 주변화하여 최종 클래스 확률을 얻는다. 이는 검색된 여러 문서를 고려해 최종 판단을 내리는 방식이다.

부록 F. Null 문서

저자들은 유용한 정보를 검색하지 못하는 경우를 모델링하기 위해 빈 문서를 추가로 검색하는 Null document 메커니즘을 실험했다. 이 방식은 k개 문서에 더해 빈 문서를 하나 추가하고, k+1개 예측을 주변화한다. Null 문서의 로짓은 학습된 문서 임베딩, 정적 편향, 또는 신경망으로 예측하는 방법을 시도했다.

하지만 이 방법들은 성능을 개선하지 못했으므로 최종 모델에서는 제외했다. Open MS-MARCO처럼 유용한 문서를 항상 검색할 수 없는 과제에서도, 모델은 검색이 덜 도움이 되는 질문에 대해 특정 문서 집합을 반복적으로 검색하는 경향을 학습했다. 따라서 RAG에는 별도의 Null 문서 메커니즘이 반드시 필요하지 않을 수 있다.

부록 G. 파라미터 수

RAG 모델은 DPR의 BERT-base 질문 인코더와 문서 인코더를 포함한다. 각 인코더는 약 1억 1천만 개 파라미터를 가지지만, 문서 인코더는 직접 학습하지 않는다. BART-large 생성기는 약 4억 6백만 개의 학습 가능한 파라미터를 가진다. 전체적으로 RAG는 약 6억 2천 6백만 개의 학습 가능한 파라미터를 사용한다.

가장 강한 폐쇄형 책 오픈 도메인 QA 모델인 T5-11B는 110억 개 파라미터를 가진다. 비슷한 크기의 T5-large와 비교하면, RAG는 훨씬 적은 학습 가능 파라미터로 강한 오픈 도메인 QA 성능을 달성한다. 비파라미터 메모리 인덱스는 학습 가능한 파라미터는 아니며, 약 2,100만 개의 728차원 벡터로 이루어진다.

부록 H. 검색 붕괴

예비 실험에서 스토리 생성 같은 일부 과제에서는 검색 구성요소가 입력과 관계없이 같은 문서를 반복적으로 검색하는 검색 붕괴 현상이 나타났다. 이런 경우 생성기는 검색 문서를 무시하도록 학습하고, RAG 모델은 BART와 거의 같은 방식으로 동작한다.

검색 붕괴를 피하려면 검색이 실제로 과제 해결에 도움이 되는 지식 집약적 과제에서 RAG를 사용하는 것이 중요하다. 또한 검색된 문서가 출력 생성에 기여하는지 분석하는 과정이 필요하다.

부록 I. 데이터셋별 인스턴스 수

논문은 각 데이터셋의 학습, 개발, 테스트 인스턴스 수를 표로 보고한다. 이 정보는 실험 규모와 비교 가능성을 이해하는 데 사용된다. 데이터셋마다 공개 테스트 세트의 사용 가능 여부가 다르므로, 일부 과제에서는 공개 개발 세트를 평가에 사용한다.
